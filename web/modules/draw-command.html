Module: DrawCommand

Source: include/DrawCommand.h, src/DrawCommand.cpp

The largest and most complex module. Implements the entire annotation pipeline for the draw command.

Responsibilities

  • Iterate files in the working directory
  • Manage image backups (create on first run, restore on subsequent runs)
  • Detect BMP bit-depth from file headers
  • Load images via OpenCV
  • Look up sprite rows from SpriteSheet
  • Draw dashed rectangles on the loaded image matrix
  • Draw sprite sequence numbers using built-in pixel fonts
  • Save images preserving original bit-depth

Key Private Methods

MethodPurpose
readBmpBpp(file)Read BMP bit count from header offset 28
writeBmp16BGR565(out, mat)Write 16-bit RGB565 BMP file with BI_BITFIELDS header
toScalar(Color)Convert RGB Color to OpenCV BGR Scalar
drawDashedRect(img, rect, color)Draw 1-on-3-off dashed rectangle border
drawNumber(img, n, endX, endY, doubleSize, opt)Draw multi-digit number right-aligned at given point
drawDigitBlock(img, digit, x, y, scale, ...)Render a single digit using 3×5 bitmap font
digitMask(ch)Return the 15-element boolean bitmap for a digit character

Pixel Font Data

Both fonts are stored as static boolean arrays at file scope in DrawCommand.cpp.

  • Small font: DIGIT_0 … DIGIT_9 — 15 booleans each (3 columns × 5 rows)
  • Large font: D0 … D9 — 60 booleans each (6 columns × 10 rows)

The large font bitmaps are hand-crafted to match the original Java implementation output. They are not simply scaled versions of the small font.

BMP Write Path

if ext == ".blp"  → writeBmp16BGR565()
else if bpp == 16 → writeBmp16BGR565()
else if bpp == 8  → cv::imwrite()
else              → cv::imwrite()

Dependencies

  • SpriteSheet — for CSV data lookup
  • SpriteUtilsOptions — for typed configuration
  • Utils::copyFile() — for backup management
  • OpenCV (cv::Mat, cv::imread, cv::imwrite, cv::rectangle, cv::line)

Limitations

  • Only reads bit depth from BMP files; non-BMP files bypass the depth check entirely.
  • The custom writer requires CV_8UC3 input; other mat types throw.
  • Number rendering has no overflow protection — numbers rendered on very small sprites may clip or overlap the rectangle border.
