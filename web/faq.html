FAQ

Why does the tool modify my images in place?

sprite-utils writes annotations directly onto the image files in the working directory. It creates .backup files automatically before the first modification. This design matches its role as a visual debugging tool — you view the annotated images, fix the CSV, then re-run.

How do I restore my original images?

Copy each *.backup file back to its original name: 

cp player.bmp.backup player.bmp

A batch restore: 

for f in *.backup; do cp "$f" "${f%.backup}"; done

The planned restore command would automate this, but it is not yet implemented.

What happens if I run draw twice?

On the second run, the tool detects the existing .backup file, restores the original from backup, then draws fresh annotations. You always get a clean annotation pass regardless of how many times you run.

Why is my CSV rejected with "Invalid initial row or column"?

Each image's first entry in the CSV must have row=1 and column=1. If you start numbering from a different row or column, the parser rejects it. Check that the very first row for each image file starts with row 1, column 1.

Can I have gaps in row or column numbers?

No. Row numbers must increment by exactly 1, and within each row, column numbers must increment by exactly 1. Gaps cause a SpriteUtilsException.

Why does the help command show different option names than what actually works?

The help text in src/HelpCommand.cpp is out of date and does not reflect the actual implemented options. Use the Command-Line Reference in this documentation for accurate information.

What is the .computed.csv file?

After parsing, sprite-utils writes <spritesheet>.computed.csv alongside the original CSV. This file contains all rows with x, height, and numberPerSheet fully resolved. It is useful for auditing computed values.

Can I use PNG files instead of BMP?

Yes. sprite-utils uses OpenCV for image I/O, so any format OpenCV supports can be read and written. However, bit-depth preservation is only specially handled for BMP and BLP files. PNG files are handled by OpenCV's default codecs.

What is a BLP file?

BLP is a game texture format used by some games in the Open Eggbert project family. sprite-utils treats BLP files as 16-bit RGB565 BMP files and always writes them back using the custom RGB565 writer.

Does sprite-utils support big-endian systems?

The BMP bit-depth reader includes a big-endian byte-swap: #if __BYTE_ORDER__ == __ORDER_BIG_ENDIAN__. This suggests intent to support big-endian, but actual big-endian testing is Needs verification.

Can I use sprite-utils as a library?

No. The build system compiles sprite-utils as a standalone executable. There is no shared library target in CMakeLists.txt. You could invoke it as a subprocess from another tool, or restructure it to build as a library, but that is not currently supported.

What version is this?

sprite_utils version
# Output: Sprite Utils 0.0.0-SNAPSHOT
