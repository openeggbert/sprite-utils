Debugging

Building with Debug Symbols

cmake -B build-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug

Debugging CSV Parsing Issues

Every successfully parsed row is printed to stdout after processing. If a row is wrong, check the stdout output to see what the tool computed for that row.

The .computed.csv file is your best friend: it shows the final resolved values for every row, including computed x, height, and numberPerSheet.

Common CSV Errors

Error MessageCauseFix
Invalid initial row or column for file X First row for a file doesn't have row=1, column=1 Make the first entry for that file have row=1, col=1
Unexpected row for X Row numbers are not sequential or go backwards Ensure row values monotonically increase by 1
Unexpected column for X Column numbers within a row are not sequential Ensure column values increment by exactly 1 within a row
CSV line does not contain enough columns Fewer than 10 semicolons in a data row Add missing semicolons to reach at least 10 columns
Could not compute X for Column > 1 but no previous row available Ensure the previous row exists and is valid

Debugging Image Issues

If the annotated image looks wrong:

  1. Open spritesheet.csv.computed.csv and check the x, y, width, height values for the problem sprite.
  2. Verify your image dimensions match what you expect.
  3. Check that y + height does not exceed the image height.
  4. For BMP files, verify the bit depth matches what the tool detected.

Debugging BMP Handling

The tool reads the BMP bit-depth from the raw header before OpenCV loads the image. If you get a "Not a BMP file" error for a file that should be processable, verify:

  • The file is not corrupted (first two bytes should be B and M).
  • The file is truly a BMP or BLP file. For non-BMP image formats, the readBmpBpp call will fail.

Using GDB

gdb ./build-debug/sprite_utils
(gdb) run draw --dir /path/to/sprites
(gdb) bt   # backtrace on crash

Adding Debug Output

The simplest way to add debug output is to add std::cout or std::cerr statements. The codebase already uses cout extensively. No logging framework is present.
