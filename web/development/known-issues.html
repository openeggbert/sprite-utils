Known Issues

Code quality issues and bugs identified from reading the source. None are confirmed by a test suite.

Bugs

readBmpBpp Called on Non-BMP Files

In DrawCommand::run(), readBmpBpp(imageFile) is called for every file in the working directory before checking the extension. If the directory contains non-BMP files (e.g., PNG, JPEG), the function will throw because the BMP signature check fails. This prevents processing any non-BMP file even if OpenCV supports it.
Source: src/DrawCommand.cpp, DrawCommand::run()

Global Static State in SpriteSheet

SpriteSheet::lastX, ::lastWidth, ::lastHeight are static class members; and lastSpriteSheetRow is a static local at file scope. Creating two SpriteSheet instances or reusing the class would produce corrupt results.
Source: src/SpriteSheet.cpp lines 33–36

Code Quality Issues

const_cast in SpriteUtils::run()

SpriteUtilsArgs constructor takes vector<string>& (non-const), but SpriteUtils::run(const vector<string>&) must const_cast to pass it. The constructor does not modify the vector and should accept const&.
Source: src/SpriteUtils.cpp line 35

Outdated Help Text

The text printed by sprite_utils help references option names that don't exist (color, files, groups, positon [sic], number-per-group). The actual options use -- prefixes and different names.
Source: src/HelpCommand.cpp

SpriteUtilsCommand Enum Unused

The enum in include/SpriteUtilsCommand.h defines DRAW, RESTORE, EXTRACT, GIFS, HELP, VERSION but is not used anywhere in the dispatcher (SpriteUtils.cpp). The dispatcher uses raw string comparison.

drawDigitBlock Background Uses Same Color Regardless

In DrawCommand::drawDigitBlock(), the background colour is computed as: cv::Scalar bg = backgroundWhite ? cv::Scalar(255,255,255) : cv::Scalar(255,255,255); Both branches are identical — the backgroundWhite parameter has no effect.
Source: src/DrawCommand.cpp line 323

No Tests

There is no test suite. Any change to parsing, computation, or drawing logic cannot be automatically verified. All testing is manual.

validateFirstRow Takes Non-Const Reference via const_cast

validateRow(const SpriteSheetRow&) calls validateFirstRow(const_cast<SpriteSheetRow&>(spriteSheetRow)) because validateFirstRow needs to modify the row (set numberPerSheet). Better design would take a non-const parameter from the start.
Source: src/SpriteSheet.cpp line 128
