Coding Style

Conventions observed from the source code. No formal style guide document is present.

Naming

  • Classes: UpperCamelCase (SpriteSheet, DrawCommand)
  • Methods: lowerCamelCase (getSpriteSheetRows, processLine)
  • Member variables: lowerCamelCase (numberInGroup, spriteUtilsArgs)
  • Constants: UPPER_SNAKE_CASE (DIGIT_0, NAME) or constexpr const char*
  • Local variables: lowerCamelCase
  • Parameters: lowerCamelCase; sometimes suffixed with In to avoid name collision (spriteUtilsArgsIn)

File Organization

  • Headers in include/, implementations in src/
  • One class per header/implementation pair
  • Include guards use #ifndef FOO_H / #define FOO_H style (some files use #pragma once)
  • MIT licence header at the top of every source file (enforced by add_license_after_includes.sh)

C++ Standard Usage

  • std::optional for nullable values
  • std::filesystem::path for file paths
  • std::unique_ptr for owned objects in the command registry
  • std::unordered_map for the command registry
  • std::string::starts_with / std::string::ends_with (C++20)
  • Range-based for loops
  • Structured bindings in range-for (for (const auto& e : map))

Error Handling

  • All errors throw SpriteUtilsException (wraps std::runtime_error)
  • Some I/O errors also throw std::invalid_argument from SpriteSheetRow constructor
  • No error codes or return-value-based error propagation
  • No try/catch in main()

Comments

  • Section divider comments used in DrawCommand.cpp: // ---- Section name ----
  • Some Java-style comments from the original Java implementation are preserved: // Equivalent to Java: String getName();
  • @author Javadoc-style tags appear in some headers

IDE

The project was developed with CLion (JetBrains). The .idea/ directory contains IDE project files. The .clangd file configures clangd for -std=c++23.
