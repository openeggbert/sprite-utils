Sprite Processing

This page documents the sprite annotation pipeline in sprite-utils — what happens to images and how sprite definitions are applied.

What sprite-utils Currently Does

At present, sprite-utils implements annotation only: it draws visual markers on top of existing images to help verify sprite coordinates. It does not extract, cut, or export individual sprites (those are planned future commands).

Coordinate System

The coordinate system follows the standard image convention used by OpenCV:

  • Origin (0,0): top-left corner of the image.
  • X: increases rightward.
  • Y: increases downward.
  • A sprite rectangle is defined by (x, y, width, height).

Dashed Rectangle Drawing

The dashed rectangle is drawn by DrawCommand::drawDashedRect() (src/DrawCommand.cpp). The pattern is 1 pixel on, 3 pixels off along each side. All four sides are drawn with separate loops.

The rectangle uses cv::LINE_8 (8-connected) and 1-pixel line width. The minimum rectangle size is 1×1 pixel (enforced with std::max(1, width)).

Default colour: red (255, 0, 0 in RGB = 0, 0, 255 in OpenCV's BGR).

Sprite Number Drawing

When enabled (--draw-number true), the sequential sprite number (field numberPerSheet) is drawn inside the rectangle at the bottom-right corner.

Small Font (3×5 pixels)

Digits 0–9 are rendered using hard-coded 3×5 pixel bitmaps stored as boolean arrays. Each pixel is drawn as a 1×1 rectangle (scale=1).

  • Foreground: yellow (0,255,255 in BGR) if no background, black if background enabled.
  • Background: white rectangle (255,255,255) padded 1 pixel around the digit.
  • Spacing between digits: 4 pixels (x offset per digit).
  • Position: bottom-right of the sprite rectangle minus 2px from each edge.

Large Font (10×6 pixels)

Digits 0–9 are rendered using separately defined 10×6 pixel bitmaps (not scaled from small font). These match the output of the original Java implementation.

  • Foreground: yellow if no background, black if background enabled.
  • Background: white rectangle padded 1 pixel around the digit.
  • Spacing between digits: 7 pixels.
  • Automatic fallback to small font if sprite.width < 23.

Sprite Sheet Structure

Sprites are organized in the CSV by:

  • File: which image file the sprite belongs to.
  • Group: logical animation group (e.g. walk, run).
  • Row: row of sprites on the sheet (1-based).
  • Column: column within the row (1-based).
  • numberPerSheet: auto-computed sequential number across all sprites in all files.

Limitations of Current Implementation

No Sprite Extraction

sprite-utils currently only draws annotations. It cannot extract individual sprites to separate image files. The extract command is planned but not implemented.

No Transparency Handling

There is no alpha channel processing in the current implementation. Transparency information in the source images is not considered during rectangle drawing.

No Palette Support

Palette (indexed colour) images are not explicitly handled. OpenCV may convert them automatically, but the results with 8-bit indexed BMP images are Needs verification.

No Animation Frame Export

The gifs command is planned (enum defined in SpriteUtilsCommand.h) but not yet implemented.
