Usage

This page explains the typical workflow for using sprite-utils in a sprite asset pipeline. For complete option documentation see Command-Line Reference.

Typical Workflow

  1. Create or maintain a sprite-sheet CSV file that defines sprite rectangles.
  2. Run sprite_utils draw to annotate the source images.
  3. Open the annotated images in any image viewer to verify sprite boundaries.
  4. Edit the CSV if any rectangle is wrong, then re-run — the tool auto-restores backups.
  5. When finished auditing, the .backup files hold the clean originals.

Basic Draw Invocation

sprite_utils draw --dir /path/to/asset/directory

This does the following:

  1. Looks for /path/to/asset/directory/spritesheet.csv.
  2. Iterates every file in that directory (skipping .backup files).
  3. For each file that has rows in the CSV, reads or creates a backup, loads the image, draws annotations, and saves.
  4. Writes spritesheet.csv.computed.csv with all resolved coordinate values.

What Gets Drawn

  • Dashed rectangle — a 1-pixel dashed border (1 on, 3 off pattern) drawn in the configured colour (default red).
  • Number — the sequential sprite number within the sheet, drawn in small (3×5) or large (10×6) pixel font at the bottom-right of the rectangle. Yellow when drawn without background; black when drawn with white background.

Backup and Restore Behaviour

The backup mechanism is critical to understand:

  • On first run: the original image is copied to image.bmp.backup, then the original is annotated and overwritten.
  • On subsequent runs: the tool detects the backup exists, restores the original from backup, then re-draws fresh annotations.
  • This means you can safely re-run after changing the CSV — you always get annotations on a clean image.

Protecting Originals

Never delete the .backup files while you still need the clean originals. The annotated images are treated as disposable; the backups are the source of truth.

Processing a Single File

sprite_utils draw \
  --dir /path/to/assets \
  --file-name enemies.bmp

After processing enemies.bmp, the loop breaks early regardless of other files in the directory.

Filtering by Row

sprite_utils draw \
  --dir /path/to/assets \
  --file-name player.bmp \
  --row 3

Only sprites in row 3 (as defined in the CSV) are drawn on player.bmp.

Stdout Output

sprite-utils prints progress to stdout:

  • Sprite Utils - tool used to work with sprites — on startup
  • Found arg: --key=value — for each parsed argument
  • Going to process images in directory: /path — before processing
  • Each resolved CSV row is printed as it is processed

Error messages go to stderr.
