File Formats

Sprite Sheet CSV

The primary input format for sprite-utils is a semicolon-delimited CSV file that describes the rectangular regions of sprites within image files.

Implemented in: include/SpriteSheetRow.h, src/SpriteSheetRow.cpp, src/SpriteSheet.cpp

Delimiter

Field separator: ; (semicolon). This is different from comma-separated CSV — do not use commas.

Header Line

The first line of the file is a header and is skipped by the parser. Its content is preserved in the computed output file.

Columns

#Column NameTypeRequiredDescription
0filestringYesImage filename (not full path), e.g. player.bmp
1groupstringYesLogical group name for this sprite, e.g. walk
2numberInGroupintegerYes1-based index of this sprite within its group
3rowintegerYesRow of this sprite on the sheet (starts at 1)
4columnintegerYesColumn of this sprite on the sheet row (starts at 1)
5xinteger or emptyNoX pixel offset. If empty, computed automatically (0 for column 1, previous x + previous width for column >1)
6yintegerYesY pixel offset of the sprite rectangle
7widthintegerYesWidth of the sprite in pixels
8heightintegerYes (may be 0)Height of the sprite in pixels. If 0, computed from previous row. For column >1, may be negated to indicate relative height delta.
9notesstringNoFree-text notes for this sprite
10tagsstringNoTags associated with this sprite
11numberPerSheetintegerAutoComputed: sequential number of this sprite across the whole sheet. Do not set manually — it is always computed by the tool.

Minimum Columns

The parser requires at least 10 columns per data row (indices 0–9). Rows with fewer columns are rejected with an error.

Automatic X Computation

If the x field is empty, the parser computes it:

  • For column == 1: x = 0
  • For column > 1: x = previousRow.x + previousRow.width

Height Computation

When height == 0, it inherits from the previous row:
height = previousRow.height + (-spriteSheetRow.height)
(The negative sign allows encoding a height delta relative to the previous sprite.)

For column > 1, if abs(height) ≥ abs(previousHeight) and the column is > 2, the height value is negated. This is a special encoding in the CSV for multi-column sprite rows; see src/SpriteSheet.cpp:processLine.

Stop Sentinel

Processing stops when a line containing the text skipskip is encountered. Any lines after skipskip are ignored. This allows notes or disabled rows to be placed below the sentinel.

First-Row Validation

The first data row for each image file must have row == 1 and column == 1. Violation throws a SpriteUtilsException.

Sequential Row/Column Validation

Within a single image file's rows, the row value must be monotonically non-decreasing. Within the same row, column must increment by exactly 1. Violations throw a SpriteUtilsException.

Sprite ID

Each sprite has a computed ID formed as: file__group__numberInGroup (double-underscore delimiter). This is used in error messages.

Example CSV

file;group;numberInGroup;row;column;x;y;width;height;notes;tags;numberPerSheet
player.bmp;walk;1;1;1;;0;32;32;;;
player.bmp;walk;2;1;2;;;32;0;;;
player.bmp;run;1;2;1;;32;40;40;;;
enemy.bmp;idle;1;1;1;;0;24;24;;;
enemy.bmp;idle;2;1;2;;;24;0;;;
skipskip

Computed CSV Output

After parsing, a file named <original-name>.computed.csv is written next to the sprite sheet. This file contains all rows with fully resolved x, height, and numberPerSheet values. It is useful for auditing what the tool actually computed.

Backup Files (.backup)

Every processed image gets a sibling file with .backup appended, e.g. player.bmp.backup. This is a byte-for-byte copy of the image before annotation. The tool uses these files to restore clean images on subsequent runs.

Backup files are excluded from processing (the tool skips any filename ending in .backup).
