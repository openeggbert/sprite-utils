Overview

sprite-utils is a command-line tool written in C++23 that helps game developers visually inspect and verify sprite coordinates stored in CSV sprite-sheet definition files.

What is sprite-utils?

In 2D game development, a sprite sheet is a large image containing many smaller sprites (character frames, tiles, UI elements). Each sprite occupies a rectangular region defined by x, y, width, and height coordinates. Maintaining these coordinates accurately in a text file is error-prone. sprite-utils solves this by annotating the actual source images with visible rectangles and numbers so developers can immediately see whether a sprite definition is correct.

The tool reads a semicolon-delimited CSV file that maps sprite groups to pixel rectangles on named image files. It then overlays dashed red rectangles (or any configurable colour) and optional sequence numbers on top of the images.

Project Type

sprite-utils is a pure command-line tool. It is not a library intended for linking into other programs. The compiled binary is sprite_utils.

Relationship to Open Eggbert

sprite-utils is developed as part of the Open Eggbert / Free Eggbert / Galaxy Eggbert project family. It handles sprite assets for those games, which use BMP and BLP image files with specific bit-depth requirements (including 16-bit RGB565). The tool's support for BLP files and for preserving original BMP bit-depths reflects those game asset pipeline requirements.

Supported Image Formats

The tool reads and writes images using OpenCV. The formats it handles specially are:

  • BMP (16-bit RGB565) — read and written with a custom bit-preserving writer.
  • BMP (8-bit grayscale) — read via OpenCV, written back via OpenCV.
  • BLP — treated as 16-bit RGB565 BMP; written with the custom RGB565 writer.
  • Other OpenCV-supported formats (PNG, JPEG, etc.) — delegated to cv::imwrite.

See Image Formats for details.

OpenSSL is referenced in CMakeLists.txt but is commented out and not actually used. It is not required.

Supported Platforms

The build system uses standard CMake and the C++ standard library. The primary development platform is Linux (based on repository context). Windows and macOS support is Needs verification — the code uses std::filesystem and #if __BYTE_ORDER__ guards which suggest portability intent, but only Linux has been verified from the repository evidence.
