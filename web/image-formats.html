Image Formats

sprite-utils uses OpenCV for all image I/O but implements custom write paths for specific bit-depths to preserve the original format. This page documents exactly what is handled and how.

Read Path

All images are loaded with cv::imread(path, cv::IMREAD_UNCHANGED). If the image is single-channel (grayscale), it is immediately converted to BGR with cv::cvtColor(..., cv::COLOR_GRAY2BGR) before processing.

Write Path — Decision Logic

After drawing, the save path depends on the file extension and the original bit-depth (read from the BMP header before loading via OpenCV): 

if extension == ".blp"    → writeBmp16BGR565()   [always RGB565]
else if bpp == 16         → writeBmp16BGR565()   [preserve 16-bit]
else if bpp == 8          → cv::imwrite()        [OpenCV handles]
else                      → cv::imwrite()        [OpenCV handles]

Source: src/DrawCommand.cpp, DrawCommand::run()

Supported Formats

ExtensionReadWriteNotes
.bmp (16-bit RGB565) OpenCV Custom writer Original bit-depth detected from BMP header offset 28. Written as BI_BITFIELDS BMP with RGB565 masks.
.bmp (8-bit grayscale) OpenCV OpenCV After detection, delegated to cv::imwrite.
.bmp (other depths) OpenCV OpenCV Delegated to cv::imwrite.
.blp OpenCV Custom writer (RGB565) BLP is treated as a renamed BMP. Always written back as 16-bit RGB565. This matches the Open Eggbert asset format.
.png, .jpg, etc. OpenCV OpenCV Any format OpenCV supports can be read and written. Bit-depth check only applies to BMP/BLP.

BMP 16-bit RGB565 — Custom Writer

Implemented in DrawCommand::writeBmp16BGR565() (src/DrawCommand.cpp). This function:

  1. Accepts a BGR8 cv::Mat.
  2. Converts each pixel to RGB565: R=5 bits, G=6 bits, B=5 bits.
  3. Writes a valid BMP file with BI_BITFIELDS compression (compression type 3) and the correct RGB565 masks.
  4. Stores rows bottom-up as per the BMP specification.
  5. Uses 4-byte row alignment.

RGB565 Encoding

uint16_t b5 = (B >> 3) & 0x1F;
uint16_t g6 = (G >> 2) & 0x3F;
uint16_t r5 = (R >> 3) & 0x1F;
uint16_t rgb565 = (r5 << 11) | (g6 << 5) | b5;

Masks in the BMP header: R=0xF800, G=0x07E0, B=0x001F.

BMP Bit-Depth Detection

Implemented in DrawCommand::readBmpBpp() (src/DrawCommand.cpp).

Reads offset 28 of the BMP file header (biBitCount field). Handles big-endian byte swapping via #if __BYTE_ORDER__ == __ORDER_BIG_ENDIAN__. Returns a uint16_t bit count (e.g. 16, 8, 24, 32).

If the BMP header is shorter than 54 bytes, or the signature is not BM, a SpriteUtilsException is thrown.

Sample Images in Repository

The repository root contains two PNG sample images:

  • numbers.png — small digit font reference (3×5 pixel digits)
  • numbers_double_sized.png — large digit font reference (10×6 pixel digits)

These are visual references for the built-in pixel fonts used by the draw command's number rendering. They are not used by the code at runtime.

Needs Verification

The exact behaviour when OpenCV is given a BMP file with an unsupported or unusual bit-depth (e.g. 1-bit or 4-bit) is not confirmed from the source. It would likely fall through to the OpenCV default path, but the output quality is unverified.
