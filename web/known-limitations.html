Known Limitations

Functional Limitations

No Sprite Extraction

sprite-utils can only annotate images. It cannot cut individual sprites from a sheet into separate files. The planned extract command is not yet implemented.

No Restore Command

There is no restore command to restore all images from backups in one step. To restore manually, copy each .backup file back to its original name.

No GIF/Animation Export

The gifs command is not implemented. Animation frames cannot be exported.

CSV Format Limitations

  • The CSV delimiter is hardcoded to semicolon (;). There is no way to change it.
  • The first row for each file must have row==1, column==1. Sparse sprite sheets (starting at non-1 rows) are not supported.
  • Row and column values must be strictly sequential — no gaps allowed.
  • The height encoding for multi-column rows (negation for column > 1) is a non-obvious convention that can be confusing.
  • The skipskip sentinel is a blunt tool — all rows after it are silently ignored, making partial processing invisible.

Image Processing Limitations

  • No transparency/alpha channel handling. If the source image has alpha, it may be dropped or mishandled depending on OpenCV's behaviour for the target format.
  • Indexed colour (palette) images are not explicitly supported. They may be automatically converted to BGR by OpenCV on read, losing palette information on write.
  • The bit-depth detection reads the BMP header directly and only handles 8-bit and 16-bit specially. 24-bit, 32-bit and other depths go through OpenCV's default path.
  • The custom RGB565 writer only handles CV_8UC3 input (BGR 8-bit). Feeding other types to this writer throws a SpriteUtilsException.

Architecture Limitations

  • No tests. There is no automated test suite, making regressions hard to catch.
  • Global static state: SpriteSheet::lastX, SpriteSheet::lastWidth, SpriteSheet::lastHeight are static class members and a static-local lastSpriteSheetRow. This makes the class non-reentrant.
  • Exceptions are not caught in main(), so any error terminates with an unhandled exception message and non-zero exit.
  • No configuration file — all options must be re-specified on every invocation.
  • Help text in HelpCommand.cpp describes options (color, files, groups, position) that do not match the actual implemented options (e.g. --rectangle-color, --file-name). The help text is out of date.

Platform Limitations

  • Only Linux has been confirmed to work from repository evidence. Windows and macOS support is unverified.
  • The add_license_after_includes.sh script uses bash; it will not work on Windows without WSL or Git Bash.

Help Text Mismatch

The text displayed by sprite_utils help references option names (color, files, groups, positon, number-per-group) that do not correspond to the actual implemented ---prefixed options. The help text appears to be a draft that was not updated when the implementation changed.
