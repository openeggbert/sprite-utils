BMP Handling

Source: src/DrawCommand.cpp

readBmpBpp(file)

Reads the bit-depth (biBitCount) from the BMP BITMAPINFOHEADER.

uint16_t DrawCommand::readBmpBpp(const path& file):
  Open file in binary mode
  Read first 54 bytes into header[54]
  if read < 54: throw "Invalid BMP header"
  if header[0] != 'B' OR header[1] != 'M': throw "Not a BMP file"
  bpp = *reinterpret_cast<uint16_t*>(&header[28])
  #if BIG_ENDIAN: swap bytes
  return bpp

Offset 28 in the BMP header corresponds to the biBitCount field of BITMAPINFOHEADER. Possible values: 1, 4, 8, 16, 24, 32.

writeBmp16BGR565(out, bgr8)

Writes a valid 16-bit RGB565 BMP file from a BGR8 OpenCV Mat.

Pixel Conversion

For each pixel (B, G, R) in BGR8:
  b5  = (B >> 3) & 0x1F   // 5 bits
  g6  = (G >> 2) & 0x3F   // 6 bits
  r5  = (R >> 3) & 0x1F   // 5 bits
  rgb565 = (r5 << 11) | (g6 << 5) | b5

BMP File Structure Written

BITMAPFILEHEADER (14 bytes):
  'B', 'M'
  fileSize (4 bytes)
  reserved (4 bytes) = 0
  pixelDataOffset = 14 + 40 + 12 = 66

BITMAPINFOHEADER (40 bytes):
  size = 40
  width (4 bytes)
  height (4 bytes, positive = bottom-up)
  planes = 1
  biBitCount = 16
  biCompression = 3 (BI_BITFIELDS)
  biSizeImage = rowStride * height
  ppmX = ppmY = 2835
  clrUsed = 0, clrImportant = 0

BITFIELDS (12 bytes):
  rMask = 0xF800
  gMask = 0x07E0
  bMask = 0x001F

Pixel data (bottom-up, 4-byte aligned rows):
  For y from height-1 downto 0:
    row of uint16_t values

Row Alignment

rowStrideOut = ((width * 2 + 3) / 4) * 4

Each row is padded to a 4-byte boundary as required by BMP specification.

Why Custom Writer?

OpenCV's cv::imwrite() does not preserve 16-bit RGB565 BMP format correctly. When saving back a 16-bit BMP through OpenCV, the output is typically 24-bit BGR. The custom writer ensures that images originally in 16-bit RGB565 format remain in that format after annotation, which is critical for game engine compatibility (especially BLP files).
